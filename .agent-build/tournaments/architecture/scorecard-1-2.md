**Scores**

- **Requirements coverage — 9.0/10.** The requirement map and package inventory cover nearly every Must, including static-first completion, the six coverage states, three-option decision support, dedicated security review, both provider paths, and the four-host release matrix; the missing safe-rendering contract means AC-5/AC-8 are not actually closed end to end.
- **Hostile-repository isolation — 7.0/10.** The VM broker, generated restricted Compose, no-network analyzers, narrow host bridge, and explicit residual risks are strong, but `GET /runs/{runId}/evidence/{evidenceId}` exposes admitted target-derived content through a “same-origin content link” (§HTTP API, Assessment and review) without a MIME allowlist, forced-download rule, isolated origin, CSP, sanitization, or safe preview contract.
- **Source immutability — 8.5/10.** Commit-only and explicit frozen-working-tree identities, a canonical snapshot manifest, read-only job mounts, and before/after integrity checks are well specified; export atomicity, hostile symlink handling, submodule/LFS treatment, and TOCTOU behavior while hashing a live local tree remain unspecified.
- **Cross-agent equivalence — 8.0/10.** Shared phase, schema, domain, evidence, and package gates correctly define outcome equivalence rather than byte identity, but the exact cross-provider conformance fixture/assertion matrix and provider interruption/resume semantics are deferred to tests rather than frozen as contracts.
- **Evidence integrity — 7.0/10.** The quarantine-to-admission-to-frozen-staging pipeline, canonical native JSON, reference/materiality gates, JCS manifest, checksum algorithm, and ZIP reopen verification are rigorous; however, the access matrix says the control plane never receives secret values and the host bridge cannot access frozen staging, while Observability says the “central redactor” seeds the final scan from known secret handles, leaving AC-5's exact seeded-secret validation unimplementable as written.
- **Resumability — 6.5/10.** SQLite jobs, attempts, leases, immutable admitted evidence, replayable events, and idempotent packaging are a sound base, but the retry-safe job catalog and per-operation recovery semantics are absent, `waiting` appears in bridge-loss behavior despite not being a job state, review rejection is not represented in the state diagram, and runtime/VM orphan reconciliation is asserted rather than contracted.
- **Portability — 6.5/10.** Multi-architecture images, native-host release gates, WSL honesty, and architecture-specific runtime adapters are appropriate, but the spec freezes `node:sqlite` through Drizzle while explicitly admitting it is unproven (§SQLite operational store), contrary to DECISIONS' requirement that the driver be selected **and validated before architecture freeze**; Node SEA and Lima lifecycle viability are likewise still open release blockers.
- **Build-lane contracts — 8.0/10.** Ownership, package boundaries, OpenAPI/SSE shapes, canonical documents, analyzer results, and bridge message envelopes enable substantial parallel work, but the security-critical bridge still types `payload`/`result` as `object`, and `runtime.call` is only an operation plus artifact/policy IDs rather than complete per-operation request, response, error, authorization, and idempotency schemas.
- **Operability — 7.0/10.** Budgets, bounded concurrency, structured logs, backup/integrity behavior, failure responses, cancellation, emergency stop, and release gates are concrete; retention/deletion, bridge/server upgrade compatibility, host-binary authenticity/rollback, disk-pressure cleanup, and an operator-visible repair workflow are not specified.
- **Simplicity — 8.0/10.** A single Fastify process, single SQLite writer, fixed phase graph, SSE, and no Redis/object store/plugin framework are disciplined choices; the custom host bridge, SEA distribution, VM lifecycle, Compose compiler, evidence protocol, and schema estate are justified by the threat model but make “simplest portable” contingent on the unresolved portability spikes.

**Overall**

**7.6/10** — equal-weight arithmetic mean. This is a strong contender with unusually good breadth, but it does not clear P1's ≥8 freeze bar because two security-critical release boundaries and several recovery/portability contracts remain for implementation lanes to invent.

**Strongest objection**

The authenticated UI origin is not isolated from hostile evidence. The spec calls the browser/control plane a trusted zone (§Trust zones) and then makes admitted evidence available through a “time-limited same-origin content link” (§HTTP API, Assessment and review). Admission, redaction, and hashing do not make repository-supplied HTML, SVG, XML, PDF, Markdown, or mislabeled bytes safe to execute. A hostile artifact served inline can run with the application's origin, call `GET /session` to obtain the CSRF token, and submit approvals, reviews, actions, or package requests as the operator. Because safe content delivery is absent from the API, artifact, and report-renderer contracts, P5/P6 would have to invent a security boundary that P1 is required to freeze.

**Other findings**

1. **Must-fix — the seeded-secret release gate has no component that can perform it.** The resource matrix gives the control plane no sandbox-secret value and gives the host bridge no frozen-staging/package access (§Resource access matrix); Security and privacy says secret values never enter the browser HTTP/SQLite/model/log/package surfaces, while Observability says a “central redactor” uses known secret handles to seed the final scan. Exact-value validation requires a deliberately defined trusted scanner/data path. Generic pattern matching cannot satisfy the brief's seeded-secret acceptance test.
2. **Must-fix — the selected SQLite boundary is not actually frozen.** §SQLite operational store selects `node:sqlite` through Drizzle but says release is blocked until compatibility is proven. DECISIONS requires selection **and validation** on Linux ARM64/x86-64 before architecture freeze, and P1 exists to freeze this shared dependency. Deferring proof to Milestone 0 allows a failed adapter spike to invalidate the data layer after downstream design.
3. **Must-fix — recovery semantics are incomplete and internally inconsistent.** The fixed job state vocabulary omits `waiting`, but §Availability says bridge-loss jobs are marked waiting. The text permits review rejection back to `running`, although the diagram omits that edge. “Retry only retry-safe job types” never enumerates those types or defines resume/reconcile behavior for source acquisition, provider sessions, build egress, VM create/start/probe/collect/destroy, admission, and partially written reports.
4. **Must-fix — the host/VM privilege boundary is an envelope, not an implementation-ready protocol.** `BridgeRequest.payload` and `BridgeResponse.result` are `object`; `runtime.call` multiplexes eight privileged operations through one generic shape. Without strict per-operation schemas, state preconditions, authorization/approval checks, response evidence, stable error codes, request-size limits, and idempotency rules, the broker and server lanes can implement incompatible or unsafe interpretations.
5. **Must-fix — secret delivery and target egress enforcement are underspecified.** The matrix allows a named target/probe consumer to receive a secret, but the spec does not freeze whether delivery is a one-shot file, tmpfs secret, environment variable, or brokered request; nor does it define zeroization, crash cleanup, log masking, process inheritance, or evidence attestation. The “logged proxy” has no contract for DNS rebinding, direct-IP bypass, TLS/SNI validation, redirect handling, destination pinning, IPv6, or build-container firewall enforcement.
6. **Should-fix — snapshot path semantics need adversarial rules.** The manifest includes symlinks and the snapshot is mounted directly into heterogeneous scanners, but there is no rule for absolute/escaping links, case/Unicode collisions at acquisition, Git submodules, LFS pointer versus fetched content, sparse repositories, special files in frozen working trees, or concurrent modification during local export. Those choices affect both source identity and scanner isolation.
7. **Should-fix — operability promises lack lifecycle contracts.** Retention is described as operator-configured, but there is no retention/deletion API, tombstone/audit behavior, or guarantee that completed packages survive SQLite cleanup. The signed SEA host bridge is a critical executable, yet signer trust, verification, protocol-version negotiation, upgrade ordering, rollback, and mismatch behavior are not frozen.
8. **Nice-to-have — performance statements are mostly limits, not service objectives.** The 250 ms/2 s UI targets name no reference hardware or percentile, and scanner/provider/VM budgets do not define expected end-to-end duration or storage forecasts for representative fixtures. This is acceptable for MVP but weakens capacity and release-test planning.

**Concrete fixes**

1. Freeze an untrusted-content delivery policy: serve raw evidence only as `attachment` with `X-Content-Type-Options: nosniff` from a cookie-less isolated origin (or never over HTTP); provide only allowlisted, size-bounded, escaped server-generated previews; ban inline active HTML/SVG/XML/PDF; define CSP and sandbox rules; and require report renderers to escape all source/model text with no arbitrary script, event handler, remote URL, or active content.
2. Add an explicit trusted final-secret-scan operation. Prefer a bridge-local scanner that receives a read-only frozen-staging snapshot plus selected secret handles and returns only match locations/fingerprints and a signed verdict; alternatively define a tightly scoped one-shot secret injection into a dedicated no-network validator. Update the resource matrix, bridge protocol, audit events, cleanup/zeroization behavior, and seeded-secret fixtures accordingly.
3. Do not freeze the driver ADR until the Node 24/Drizzle spike passes both Linux architectures. Record the exact Drizzle adapter/package/version and fallback decision; if the chosen adapter is unavailable or unstable, revise the ADR and data-layer contract before P2/P3/P4 consume it.
4. Replace prose state diagrams with machine-readable transition tables for run, phase, job, action, review, runtime, artifact, and package states. Enumerate retry-safe operations, resume tokens, lease ownership, duplicate terminal-result handling, partial-output cleanup, cancellation deadlines, orphan discovery, and recovery decisions for every privileged operation.
5. Split `runtime.call` into strict versioned operation schemas with operation-specific request/response/error unions, preconditions, approval resolution, quotas, authorization, idempotency, and audit evidence. Freeze the target-secret mount mechanism and the proxy/firewall enforcement model, including DNS/IP/redirect/TLS/IPv6 rules and teardown verification.
6. Extend the snapshot contract with non-following copy semantics, symlink/special-file rejection or normalization, submodule/LFS policy, case/Unicode collision handling, atomicity/retry rules for changing local trees, and fixtures proving analyzers cannot traverse outside `/target`.
7. Add host bridge artifact verification, protocol negotiation, upgrade/rollback ordering, retention/deletion semantics, disk-pressure policy, and operator recovery APIs/commands before calling the architecture operable.

**Verdict**

**revise** — the contender clears the breadth and conceptual-boundary bar, but misses the P1 freeze bar. It should not ship to P2–P6 until same-origin hostile evidence, exact secret scanning, the SQLite driver gate, and privileged-operation recovery/contracts are concretely resolved.
