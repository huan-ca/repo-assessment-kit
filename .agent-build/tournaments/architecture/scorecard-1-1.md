## Scores

- **Requirements coverage — 8.6/10.** The requirement-to-component map and required ZIP inventory cover almost every Must, including explicit unknowns, static-first completion, independent security review, three-way decision support, and cross-agent release gates; coverage is weakened by the absent private-SSH credential selection flow and by naming rather than freezing several required canonical documents.
- **Hostile-repository isolation — 8.9/10.** Lines 193–259 establish credible capability boundaries: disposable analyzer/provider jobs, no host socket in containers, a mount-free Lima worker, broker-only guest Docker access, a restricted Compose compiler, and offline runtime probes. The remaining weakness is that provider egress is asserted as “inference/auth egress only” without a normative enforcement contract, and the generic bridge payload/result envelopes leave security-sensitive interpretation to implementations.
- **Source immutability — 8.5/10.** Lines 269–285 correctly distinguish commit identity from a dirty working-tree snapshot and prohibit assessment access to the live local path. However, the before/after check spans “export/assessment,” so unrelated operator edits during a long run become integrity failures even though no assessment component can access the tree, and the symlink/hash and SSH-handle acquisition algorithms are not fully contracted.
- **Cross-agent equivalence — 8.3/10.** Shared phase schemas, output validation, required domains, package gates, and separate provider homes make outcome equivalence testable. Yet line 779 reduces the provider result to a generic `outputDocument`, most phase output schemas are only referenced by URI, and resume semantics are not represented in the provider input despite line 215 promising same-job resumption.
- **Evidence integrity — 8.1/10.** The one-way quarantine/admission flow, immutable derivations, semantic validators, snapshot binding, redaction boundary, and fresh-process ZIP verification are strong. The contract is internally incomplete: the release rule permits an unevidenced material finding only if visibly `unverified/conflicting`, but `Finding` and the `findings` table have no such claim state, while several canonical evidence/provenance documents have no field-level schema in this spec.
- **Resumability — 7.2/10.** Durable job attempts, leases, request IDs, immutable admitted outputs, and frozen-staging retries are good primitives. The normative lifecycle does not define the effect of pause on in-flight jobs, the bridge has no cooperative job cancel/pause/status/reconcile operation, lease heartbeats have no protocol message, and provider resumption has no prior-session field; implementers cannot realize the stated recovery behavior from the frozen contracts.
- **Portability — 7.1/10.** The spec honestly makes the four native hosts, Lima/rootless Docker, browser/ZAP, SEA artifacts, and both providers release gates. However, line 181 freezes `node:sqlite` plus Drizzle before the DECISIONS-required Linux ARM64/x86-64 validation, then defers that proof to Milestone 0, while Lima, SEA, Claude, and ARM64 browser operation are all still unproven critical-path choices.
- **Build-lane contracts — 6.6/10.** Ownership, package boundaries, an HTTP surface, canonical vocabularies, and fixture-first sequencing are useful. But the host bridge uses `payload: object` and `result?: object` (lines 719–743), `runtime.call` has no per-operation input/output/error schemas, analyzer arrays are untyped, artifact byte handoff is unspecified, many HTTP endpoints promise only “summaries,” and seven of the ten canonical documents are content lists rather than implementation-ready contracts.
- **Operability — 7.8/10.** Budgets, failure behavior, structured logs, emergency stop, SQLite integrity checks, replayable SSE, package verification, and explicit release blockers are unusually concrete. Operators still lack a coherent private-SSH handle flow, an in-flight pause/cancel status model, a defined bridge compatibility/reconnect negotiation, and a persisted/enforced single-active-run lease in the data model.
- **Simplicity — 6.9/10.** A modular monolith and SQLite avoid unnecessary distributed infrastructure, and most process separation follows real trust boundaries. The MVP nevertheless commits to four native SEA binaries, Lima lifecycle management, a custom runtime broker/Compose compiler, eight analyzer families, a large native schema family, dual providers, dual human reviews, and optional age wrapping before the critical contracts and feasibility spikes are complete.

## Overall

**7.8/10.** The architectural direction is credible and security-conscious, but it does not clear P1’s implementation-ready contract-freeze bar. Its largest correctness risks sit at the exact host/job/runtime seams that backend, DevOps, and provider lanes must implement independently.

## Strongest objection

**Must-fix: the internal execution protocol cannot implement the lifecycle the architecture promises.** The run API exposes `pause`, `resume`, `cancel`, and `retry-job` (lines 619–630), line 312 promises cooperative cancellation before emergency stop, line 349 depends on lease heartbeats, and line 215 allows resuming an interrupted provider job. But the supposedly fixed host-bridge union at lines 719–758 has only start-style analyzer/provider calls, runtime operations, run-wide `emergency.stop`, and generic `payload`/`result` objects. It has no job pause/cancel/status/reconcile message, no heartbeat sequence or terminal-result rule, and no prior provider session/resume token in the job input at lines 764–776. The analyzer and runtime results likewise omit normative per-operation result and error shapes. Backend and host/provider lanes must therefore invent cancellation races, duplicate terminal-result handling, restart reconciliation, and artifact-finalization semantics. Those choices affect evidence immutability and whether a cancelled or retried job can be reported as complete, so they cannot safely be deferred beyond P1.

## Other findings

1. **Must-fix — the architecture violates the frozen SQLite-driver gate.** DECISIONS requires P1/research to select *and validate* a stable driver on Linux ARM64 and x86-64 before freezing. Line 181 selects `node:sqlite` through Drizzle but explicitly leaves migrations, locking, interruption, backup/restore, and both architectures unproven; lines 981–983 move those spikes into Milestone 0. This is not merely a release test because schema, migration, backup, and concurrency design depend on the adapter actually working.
2. **Must-fix — most canonical contracts are not actually frozen.** Lines 408–419 list ten documents, but lines 421–496 define only partial `ControlResult`, `EvidenceEntity`, and `Finding` shapes. `run`, target snapshot, product assertions, PROV activities/agents, coverage/limitations, decision, artifacts, export profile, manifest, and tool invocation remain prose inventories. P1 explicitly had to freeze these schemas before P2/P3/P5/P6; Milestone 0’s instruction to “Create RAK 1 schemas” confirms the work was deferred.
3. **Must-fix — the bridge protocol is typed in name only.** `BridgeRequest.payload` and `BridgeResponse.result` are `object` (lines 719–743); the payload table supplies only terse structural sketches. There is no protocol compatibility negotiation, response sequencing, result-code registry, artifact transfer/finalization contract, bounded diagnostic schema, or rule for what duplicate `running` and terminal messages mean. A privileged host boundary must fail closed on a normative schema, not on implementation-specific interpretation.
4. **Must-fix — runtime operations and credential delivery are not buildable contracts.** `runtime.call` is only `{runtimeId, operation, inputArtifactIds, policyId, approvalIds}` (line 754), while `compile`, `build`, `start`, `probe`, and `collect` have no operation-specific prerequisites, outputs, side effects, state transitions, secret-binding fields, or coverage/error mapping. The CLI registers a secret only for `target|browser` (line 564), but no contract maps it to a service environment/file or a browser authentication step.
5. **Must-fix — the private SSH flow is internally disconnected.** The host CLI exposes no SSH credential consumer (lines 562–567), `POST /runs` cannot select an SSH handle (lines 575–592), but `snapshot.acquire` unexpectedly accepts `sshHandleId?` (line 750). This leaves private-clone credential choice, host `~/.ssh` fallback, revocation, and audit behavior to launcher implementation, undermining both usability and artifact-hygiene claims.
6. **Must-fix — finding uncertainty cannot satisfy the validator’s own rule.** The release gate says every material finding must have evidence or be visibly `unverified/conflicting`. `decision_factors` has `claimState` for that purpose (lines 377–379), but `findings` and `Finding` provide only validation state and evidence IDs (lines 374–375 and 475–495). The model cannot represent a material suspected issue that is explicitly unverified without either dropping it or abusing `disputed`/`invalidated`.
7. **Must-fix — the decision comparison does not enforce the brief’s common criteria.** `criteriaVersion` and an unconstrained `criterion` string (lines 377–378) do not require all three options to use the identical set of recoverability, boundaries, security/engineering risk, critical parity, scale, and rebuild-feasibility criteria. “Common criteria” at line 417 is an assertion, not a semantic rule, so providers can produce schema-valid but non-comparable recommendations.
8. **Should-fix — lifecycle transitions conflict with API behavior.** Line 687 returns a rejected review to `running`, but that transition and its required revalidation/re-review effects are absent from the state machine at lines 289–303. The graph also does not define which jobs continue during `paused`, whether packaging failure can be retried without leaving `failed`, or which action states permit `retry-job` and `create-revision`.
9. **Should-fix — the source-integrity attestation can create false failures.** Line 282 compares the live tree before and after the whole “export/assessment” even though line 283 guarantees assessment processes never receive that path. A consultant editing an unrelated untracked file during a multi-hour assessment would invalidate an otherwise immutable exported snapshot; the attestation needs a scoped export-time check and a separately worded observation if the operator mutates the source later.
10. **Should-fix — single-active-run enforcement is not persisted.** The control-plane description promises a “single active-run lease,” but the operational model has no lease/owner/expiry record for it. A restart or second process can therefore admit two `running` rows unless downstream code invents a separate locking mechanism.

## Concrete fixes

1. Replace generic bridge objects with a versioned discriminated request/result schema per command. Add `job.status`, `job.cancel`, `job.reconcile`, and heartbeat/lease messages; define message sequencing, idempotent terminal results, timeout/error codes, artifact finalization/transfer, reconnect negotiation, and conformance fixtures.
2. Define pause, cancel, resume, retry, bridge-loss, review-rejection, and packaging-retry behavior as a transition table covering run, phase, job, provider session, VM, and evidence states. Include cooperative-cancel deadlines and the exact conversion of unfinished controls to coverage results.
3. Move the `node:sqlite`/Drizzle spike ahead of architecture freeze. Record the tested driver/adapter versions and API, generated migration path, WAL/backup algorithm, process-lock behavior, and ARM64/x86-64 results; choose a validated fallback before accepting P1 if it fails.
4. Add normative Draft 2020-12 schemas and semantic invariants for every RAK document, provider/analyzer output, bridge command/result, runtime operation, event type, approval, manifest, and API body/response. The architecture may reference checked-in schema files, but they must exist as P1 output rather than a P4/P5 task.
5. Define a fixed decision-criteria registry and require all three options to contain exactly that same versioned set, with per-factor evidence or explicit uncertainty. Add a finding `claimState` (or another lossless equivalent) so unevidenced suspected material issues can be represented honestly.
6. Add an SSH credential-handle lifecycle from host CLI registration through run selection and `snapshot.acquire`, including allowed key/config inputs, known-hosts behavior, agent-socket policy, expiry/revocation, reconnect behavior, sanitized audit fields, and assurance that no path/value enters the API or package.
7. Specify runtime operation state and credential binding: per-operation artifact types, generated Compose output, build/start/probe results, allowed secret delivery forms, browser-login limitations, scoped egress approvals, cleanup guarantees, and deterministic mapping to `RuntimeCapability`, control outcomes, and limitations.
8. Persist the single-active-run lease and bridge ownership/version in SQLite, and narrow local-source integrity attestation to distinguish assessment-caused mutation from independent operator changes after immutable export.

## Verdict

**Revise.** The contender clears the bar for architectural strategy and hostile-code containment, but misses the Phase 1 contract and correctness bar. Freeze should wait until the host/job lifecycle, canonical schemas, runtime/credential protocols, SQLite driver, and decision/finding invariants are executable without downstream invention.
